# Sentinel 升级计划（2026-11-09）

## 目标

把 Sentinel 从“架构完整的在研项目”，变成有真实运行、评测数据和真实项目结果的主力 Agent 项目。

定位：**给不懂代码的产品人和设计师用的发布前检查 Agent。** 输入网址和“用户要完成什么”，Agent 自己操作页面，用中文大白话说明哪里坏了，并附截图证据。

## 面试时的事实边界

在完成下面的工作之前：

- 可以说：实现了 Agent 架构、受控执行和证据绑定，20 项集成测试通过。
- 不能说：Agent 已用真实模型完整跑通，或已发现真实 Bug。

## 任务（按优先级）

### P0：一条命令真实跑通

- 新增命令行入口：输入网址和目标，串起生成计划、人工确认、QA 循环、Observer 判定、Bug 报告。
- 进程内运行，不依赖 PostgreSQL 和队列，降低演示和试用门槛。
- 模型接入改为兼容 OpenAI 接口，方便使用国内模型。
- **完成标准**：真实模型跑通 TaskForge 的正常流程，并发现至少一种预设故障。

### P1：评测集

- 建立 `evals/cases.jsonl` 和一键评测脚本，输出 JSON 和 Markdown 报告。
- 约 30 个用例：正常流程、预设 Bug、边界情况、页面提示词注入、工具失败。
- 每个用例重复运行，统计 Bug 发现率、误报率、故障分类准确率、步数、耗时和成本。
- **完成标准**：同一版本可重复生成报告，失败用例都有分类。

### P2：大白话中文报告

- 报告说明：用户想做什么、实际发生了什么、影响谁、怎么复现，并附截图。
- 没有证据的结论不进入报告；判断不了就写“不确定”。
- **完成标准**：找 3 位不懂代码的用户，能不靠讲解看懂报告。

### P3：真实项目

- 找约 10 个真实应用，优先是训练营同学和朋友用 AI 做的项目，**先取得对方同意**。
- 只测试对方授权的网址和测试账号，不在生产数据上做写入操作。
- 记录发现的问题数、开发者确认的真 Bug 数、误报数和反馈。
- **完成标准**：至少 10 个应用的结果表，一次根据失败案例的改版及前后对比。

### P4：更新材料

- 用真实数字更新简历，去掉“在研”。
- 公开代码前检查有没有密钥和隐私信息。
- 准备面试讲法：工具选择、何时停止、何时交给人、失败分类、与 TestSprite 的差异。
